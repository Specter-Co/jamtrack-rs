1. Add the following to your `Cargo.toml`:
    ```toml
    [dependencies]
    jamtrack-rs = { git = "git@github.com:kadu-v/jamtrack-rs.git", version = "0.1.0" }
    ```

## Visualizer

An interactive GUI visualizer is available for debugging and tuning ByteTrack parameters.

### Running the Visualizer

```bash
# With data files
cargo run --release --bin visualizer --features visualizer -- <video.mp4> <detections.json> <timestamps.json>

# Without arguments (use file picker in GUI)
cargo run --release --bin visualizer --features visualizer
```

### Features

- **Real-time parameter tuning**: Adjust ByteTrack parameters and see results immediately
- **Overlay controls**: Toggle detections, tracks, track IDs, velocities, confidence scores
- **ByteTrack mechanics view**: Step-by-step visualization of the 3-stage matching process
- **Evaluation overlays**: When ground truth is available, shows correct/incorrect track assignments
- **Frame-by-frame navigation**: Arrow keys to step through frames, space to play/pause

## Evaluation

A CLI tool for batch evaluation of tracking performance against ground truth labels.

### Running Evaluation

```bash
# Single file
cargo run --release --bin evaluate -- <detections.json> <timestamps.json>

# Batch evaluation with glob patterns
cargo run --release --bin evaluate -- "human_labeled_*.json" "timestamps_*.json"

# With config file
cargo run --release --bin evaluate -- <detections.json> <timestamps.json> --config bytetrack_config.yaml

# Evaluate at multiple FPS settings
cargo run --release --bin evaluate -- <detections.json> <timestamps.json> --tracker-fps 10,5,0
```

### Metrics

The evaluation system uses frequency-based many-to-1 matching to compute the following metrics:

| Metric | Description |
|--------|-------------|
| **Coverage** | `matched / (matched + false_match + untracked)` - Percentage of ground truth objects correctly tracked |
| **Fragmentation** | RMS of ID switches per ground truth track - measures how often tracking IDs change for the same object |
| **Confusion** | RMS of "bad" ID switches - switches where the tracker jumps to a GT ID it wasn't assigned to |
| **Tracked No Object** | Tracker outputs that don't correspond to any ground truth object. Note: this metric is hard to interpret as it may reflect incomplete labeling or detector issues rather than tracker errors |

The intermediate values (matched, false_match, untracked) are used internally to compute Coverage, Fragmentation, and Confusion but are not independently reported as primary metrics.

### Association Algorithm

1. Each tracker ID is assigned to the ground truth ID it co-occurs with most frequently across all frames
2. For each frame, a tracker output is "correct" if it's currently tracking its assigned GT ID
3. ID switches are counted when a tracker moves from one GT to another
4. Fragmentation counts all switches; Confusion counts only switches to misassigned IDs

### Data Formats

**Human-labeled format** (single JSON file):
```json
{
  "video_path": "video.mp4",
  "width": 1920,
  "height": 1080,
  "fps": 10.0,
  "frame_count": 1000,
  "detections": [
    {
      "frame_idx": 0,
      "timestamp_ms": 0,
      "bbox": [0.1, 0.2, 0.3, 0.4],
      "confidence": 0.95,
      "label": "person",
      "entity_id": 1
    }
  ]
}
```

**Timestamps file**:
```json
{
  "frame_count": 1000,
  "timestamps": [0, 100, 200, ...]
}
```

## Configuration

ByteTrack parameters can be tuned via CLI flags or YAML config:

```yaml
# Detection thresholds
min_conf: 0.1
track_thresh: 0.5
high_thresh: 0.6

# Matching IoU thresholds
high_match_iou: 0.8
low_match_iou: 0.5
activate_iou: 0.7

# Kalman filter parameters
kalman_pos: 0.05
kalman_vel: 0.00625
kalman_pos_meas: 0.05
kalman_pos_mot: 0.05
kalman_vel_mot: 0.00625
```
